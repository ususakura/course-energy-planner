# 数据与更新

只在任务需要持久记录、多个共享视图、网页或定时维护时读取。简单的一次性清单不需要搭建这一整套结构。

## 一份计划，多种视图

维护稳定的课程、作业、项目节点和工作时段编号；标题改名、时段移动或显示顺序改变时尽量保留编号，不从当前标题或列表索引重新生成。新记录用新编号，不复用已删除记录的编号。

计划内容与完成记录分开：

- **课程/任务/节点：**来源、正式截止、阶段关系、要求、剩余估时、材料、依赖和核查时间。
- **工作时段：**日期时间、关联任务/部分、建议或已确认、需要的能力与启动提示。
- **完成记录：**对象编号、状态、确认来源和更新时间。明确“完成这一步”不等于“整份作业完成”，勾选也不代表已向学校提交。
- **偏好：**确认值、建议、证据与更新时间；只保存与规划有关且用户愿意保存的信息。

周时间轴显示固定课程、工作时段和暂留约定；项目甘特图显示阶段、依赖和截止；任务看板显示状态。三者读取同一份数据，点击指向相同详情。不要让修改某一视图后其他视图仍显示旧状态。

更新计划时保留未改动对象编号和所有完成记录。若必须迁移编号，提供明确映射；对已消失对象保留历史，不把旧勾选误贴到新任务。多人或自动化可能同时写入时，采用版本检查、合并或其他适合规模的冲突处理。

## 面向日常使用的布局

让课程、任务、时间与操作占据主要空间，避免营销式首屏、口号和装饰性大标题挤走计划。信息密度、留白和视觉风格依据当前用户的偏好选择，不把某个人喜欢的日历样式设为所有人的硬性规则。材料、启动提示和完整说明按需展开，概览保留判断一天安排所需的信息。

用户希望紧凑布局时，优先减少无关区域与冗余留白，尽量在一屏呈现全天实际安排；不要靠过小字体、过小操作目标或隐藏晚间任务硬塞进去。用有代表性的完整一天在常用电脑视口中检查：最早到最晚的安排可读，重叠项能区分，时间与完成操作可识别，详情展开后可返回原位置。空间确实不足时提供清楚的滚动或缩放入口，并如实说明可见范围。

## 保存与更新能力

按用户预期选择存储。只保存在当前浏览器时明确说明范围和丢失风险，不声称跨设备同步；用户期待长期或跨设备记录时，应使用适当的持久存储。完成写入要有失败状态与重试入口，不能在保存失败时仍显示“已保存”。

新网页默认采用用户授权的受限可见范围。只带上实现任务需要的数据；不要把完整个人档案复制进可分享网站或模板。使用已有的发布、存储和身份能力，不为方便更新而扩展访问权限。

仅在用户请求定时维护时创建自动化，先检查是否已有同范围任务，优先更新而不重复创建。分别确认：

1. 未来执行环境能读取课程来源。
2. 它能读到用户的完成状态并写入计划。
3. 更新后能读回结果，且不清空勾选。

核对保存的时区、时间、启用状态和维护目标。用户要求每日/每周报告时保留该频率；纯来源监控只在有意义变化或需要行动时提醒。访问受阻的相同消息不重复轰炸。浏览器开着才能刷新与网页关闭后仍会维护，是两种不同能力。

如果只完成了网页但自动更新访问尚未接通，交付已完成部分并准确说明限制；不能用“以后会自动更新”掩盖尚未验证的连接。

## 最小检查格式

这是可选的脚本输入，不是所有工具必须采用的数据模型。正式产品可扩展其他字段。

- `timezone`：IANA时区。
- `horizon.start`、`horizon.end`：含首尾的本地日期。
- `preferences.work_minutes_ceiling`：该用户的每日预算；可用 `daily_limits` 按日期覆盖。
- `preferences.classes_count`：上课是否算入该预算；必须明确给出。
- `tasks[]`：`id`、`title`、`formal_due`（日期或带偏移的ISO时间；未知用null）、`components[]`。
- `components[]`：稳定 `id`、`kind`、`remaining_minutes.low/high`；`basis`记录估算依据。各部分为互不重叠的剩余工作。
- `sessions[]`：稳定 `id`、`start/end`（带时区偏移的ISO时间）、`kind`。
- `sessions[].kind`：`work`、`meeting`、`reserve`、`class`或`break`。
- `work`、`meeting`时段必须关联存在的 `task_id` 和 `component_id`。`reserve`可以关联，也可以是尚未发布新任务的容量预留。
- `source_checks`、`resources`、`personal_target`等可作为额外字段保存；脚本不联网核查它们。

工作、会议和预留计入预算；课程依配置计入，休息不计入。所有占用时段都检查钟表冲突。跨午夜时段按计划时区分摊到对应日期。

脚本将正式截止在规划范围内的任务用于缺口检查，按剩余估时下限减去规划窗口内、截止前已分配时段；窗口外的旧工作不抵扣当前剩余工作；高端估时仍需人工留缓冲。未来截止不要求在当前窗口内全部排完。只有日期而无钟点的截止，会提示时间未知；不会捏造23:59为正式要求。课堂内可能做项目的时间先记录为机会，实际完成后再更新剩余估时，不同时排一个重叠工作块冒充额外时间。

运行：

```sh
python3 scripts/check_plan.py path/to/plan.json
```

输出JSON包含每日占用和检查项。退出码：`0`表示没有结构或硬约束错误（仍可能有未排入警告）；`1`表示时段冲突、容量超出或截止之后安排；`2`表示输入结构无效。脚本不替用户决定优先级，不删除、跳过或移动任务，也不验证老师要求是否真实。
