# Google Calendar 联动

用户要求使用 Google Calendar 时，结合 [外部日历规则](data-and-updates.md#外部日历与用户手动调整) 阅读本页。这是联动操作指南，不是自带 OAuth、后台服务或实时同步程序。

## 先确定范围，再开始使用

沿用用户已明确的账号、读取范围、写入日历和授权，不重复询问。范围不清时，一次只问最关键的问题，例如“学习安排要写入哪个日历？”优先使用当前环境的 Google Calendar 连接器，先检查其实际支持的操作；没有访问能力时说明缺口，不声称已连接。

读取用户指定范围内的课程、约定和工作时段，核实日历时区与读写权限。仅需判断忙闲时优先使用忙闲信息；需要识别用户对学习时段的修改时才读取必要事件详情。读取日历不等于获准写入；已有明确写入授权时直接执行范围内的改动。只读或订阅日历作为约束，不尝试修改课程来源。

## 任务与日程的对应关系

- 作业保留正式截止、剩余工作、完成记录和材料链接；日历事件对应具体工作时段。移动工作时段不能移动正式截止。完成状态由真实记录决定，时间过去不等于完成。
- 为每个时段保存稳定的任务 ID、时段 ID、账号标识、`calendarId`、`eventId`、时区与上次成功同步的字段基线；API 可用时保存 `etag`。`iCalUID` 和 `eventId` 不能互换。映射属于用户的私有数据，不能放入公开 Skill 包。
- 工作事件可包含任务标题、预计时长、材料链接、第一步与停止条件；仅加入用户愿意放入目标日历的信息。保留原有描述与用户备注，不覆盖无关字段。
- 定时事件用带时区的时间；全天事件保持日期语义，结束日期不包含在事件内。日期型 DDL 未给时间时保持“时间待确认”，不要擅自变成午夜截止。跨夏令时重新核对本地上课时间。

事件字段依据：[Google Calendar Events 文档](https://developers.google.com/workspace/calendar/api/v3/reference/events)。

## 每次重排或同步

1. 先读取最新事件并完成分页，与当前计划和成功基线比较。用户手动移动、缩短、取消的时段先回写计划；固定约定、用餐和休息保留。缺失事件先按已知 ID 查询，确认是否移出读取窗口；访问失败或范围不完整不能判定删除。
2. 对计划提出必要差异：新增、移动、取消哪些工作时段，以及由此增加或减少的空闲时间。依照既有授权写入；只有范围不明或遇到真实冲突时才询问，避免每次同步重新走一遍设置。
3. 更新已匹配的事件，不按标题重新批量创建。创建结果不明时先查回映射或稳定标记，不能直接重试制造重复事件。仅修改本次需要的字段，保留提醒、参与者和重复规则；不要自动添加同学、发送邀请或更改 RSVP。
4. 写前重新核对版本，API 支持时使用条件更新。遇到并发修改先重新读取和合并，不能覆盖较新的用户操作。写后读回实际结果，再推进成功基线；部分失败列明未同步时段，保留成功记录。
5. 日程取消仅释放该时段，未完成工作保留为待安排；完成勾选、材料链接和任务 ID 不随重排丢失。当天容量不足时给出缺口和调整建议，不擅自跳过作业。

重复课程需区分整个系列和单次实例；实例用 `recurringEventId` 与 `originalStartTime` 识别。用户只移动一次课程时，只更新那次实例；范围含糊时确认，不能改整学期。参见 [重复事件指南](https://developers.google.com/workspace/calendar/api/guides/recurringevents)。

## 定期更新的真实能力

连接器只支持查询和改写时，采用已配置的每日或每周对账，明确运行时间、时区和运行依赖。只有定时任务确实创建并验证后才说“会自动更新”。没有后台能力时，可在用户打开计划或请求重排时执行读取。

自建 API 同步时，完整处理分页后才保存 `nextSyncToken`；增量请求遵守 Google 的参数约束。收到 `410` 时重建远端事件缓存并重新全量读取，保留本地任务、完成记录与映射供对账，不能清空用户计划。参见 [增量同步指南](https://developers.google.com/workspace/calendar/api/guides/sync)。

实时通知需要可访问的接收端、有效通知频道及续期机制；通知本身不含事件详情，收到通知后仍要读取变化。未实现并验证这些能力时，称为“定期对账”，不要称为实时双向同步。参见 [推送通知指南](https://developers.google.com/workspace/calendar/api/guides/push)。

提供 `.ics` 文件时称为一次性导出或导入快照，不承诺后续手动改动回传，也不依赖重复导入来更新已有事件。

## 完成时验证

用实际授权范围内的结果检查：相同计划再次同步不产生重复事件；手动移动被吸收；取消时段不把任务标为完成；完成记录和材料仍在；时区与重复实例正确。不要为了测试而修改真实课程或他人的会议。说明本次成功同步数、未处理冲突、最后核对时间及下一次更新是否已配置。
